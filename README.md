## 1. Общая концепция

Разработать браузерную 3D-игру на JavaScript (Three.js) — аркадный симулятор боевого вертолёта **Bell UH-1 Iroquois** («Huey») времён Вьетнамской войны. Игрок управляет вертолётом, переключается между местами **пилота** и **пулемётчика** (M60 у открытой двери), летает над процедурно генерируемым Вьетнамом с 4 биомами и 2 оверлеями (бомбардировки, дефолиация), сражается с вьетконговцами и зенитками, наблюдает постепенное разрушение вертолёта с отваливающимися деталями.

**Целевая платформа:** браузер (Chrome, Firefox, Edge), десктоп.
**Целевой FPS:** 60 на средних настройках (GTX 1060 / RX 580).
**Жанр:** аркадный экшен-симулятор с элементами выживания.

## 4. Процедурная генерация мира

### 4.1. Базовый рельеф

**Simplex noise + fBm (6 октав) + чанковая система 256×256 м.**

```javascript
import { createNoise2D } from 'simplex-noise';
const noise2D = createNoise2D(seed);

function generateHeightmap(resolution, scale) {
  const heightmap = new Float32Array(resolution * resolution);
  for (let x = 0; x < resolution; x++) {
    for (let z = 0; z < resolution; z++) {
      let height = 0, amp = 1, freq = 0.005;
      for (let o = 0; o < 6; o++) {
        height += noise2D(x * freq, z * freq) * amp;
        amp *= 0.5; freq *= 2;
      }
      heightmap[x * resolution + z] = height * scale;
    }
  }
  return heightmap;
}
```

Чанки генерируются асинхронно в **Web Worker**, загружаются/выгружаются по расстоянию. Дальние — упрощённые (LOD).

### 4.2. Биомы (4 основных + 2 оверлея)

| № | Биом | Рельеф | Растительность | Особенности |
|---|------|--------|----------------|-------------|
| 1 | **Джунгли** | Холмы 50–400 м | 3–4 яруса, 200–500 дер./га | Плотный навес, плохая видимость |
| 2 | **Тайнгуен** | Хребты, каньоны, 200–1000 м | Разреженные джунгли, скалы | Узкие коридоры, засады ПВО |
| 3 | **Меконг** | Плоский 0–5 м | Мангры, рис | Лабиринт проток, вода |
| 4 | **Прибрежная равнина** | 0–30 м | Пальмы, рис | Пляжи, дюны, солончаки |
| 5 | **Оверлей: Лунный пейзаж** | Воронки 4–25 м радиусом | Уничтожена | Кластеры B-52 (линии, сетки) |
| 6 | **Оверлей: Дефолиация** | Эрозия, латерит | Мёртвые стволы 50–200/га | Пятна/полосы, токсичные лужи |

**Оверлеи 5 и 6** накладываются на любой из 4 базовых биомов через маски и комбинируются между собой.

### 4.3. Смешивание текстур (splatting)

Кастомный `ShaderMaterial` с 4 текстурами и RGB-маской весов (splat map). Splat генерируется процедурно по шуму + высоте + биомной маске.

### 4.4. Растительность

- **InstancedMesh2** для деревьев (LOD, frustum culling, BVH).
- Деревья: trunk + листовые карточки (cross-billboards).
- Бамбук/кусты — без коллайдеров, только визуал.
- Крупные деревья — cylinder-коллайдеры (статические).
- Разрушаемые — kinematic → dynamic при попадании.

## 5. Физический движок (Rapier3D)

### 5.1. Инициализация

```javascript
import RAPIER from '@dimforge/rapier3d-compat';
await RAPIER.init();
const world = new RAPIER.World({ x: 0, y: -9.81, z: 0 });
world.timestep = 1/60;
```

### 5.2. Синхронизация с Three.js

`PhysicsWorld` хранит `Map<rigidBody, mesh>`, после `world.step()` копирует трансформации. **Интерполяция** между шагами физики — обязательна (см. §14.4).

### 5.3. Вертолёт

- **Rigid body:** dynamic, CCD включён, масса ~2200 кг.
- **Коллайдер:** составной (фюзеляж, хвост, шасси, кабина).
- **Силы (каждый кадр):** подъёмная (по up), тяга вперёд (по forward), боковая (по right), момент рыскания, автостабилизация по angvel.
- **Эффект земли:** +15–20% lift при высоте < 14.6 м.
- **Вихревое кольцо:** потеря lift при вертикальном снижении > 5 м/с.
- **Аркадный характер:** ручное управление отзывчивое, есть инерция, но без полной аэродинамики.

### 5.4. Стрельба

- **M60** — raycast через `world.castRay()` с фильтром коллайдеров.
- **РПГ/зенитки** — динамические rigid bodies с CCD и collision events.
- **Взрывы** — импульс всем телам в радиусе через `world.forEachRigidBody()`.

### 5.5. Разрушение

При HP зоны < порога — `detachPart()`: меш отсоединяется от Huey, создаётся отдельный rigid body с импульсом отрыва. TTL обломков 20–40 с. Максимум 50 обломков одновременно.

### 5.6. Ландшафт

- **Heightfield collider** для дальних чанков (быстро).
- **Trimesh collider** для ближних с воронками (точно).
- **Воронки** — часть heightfield-меша, не отдельные тела.
- **Вода** — триггер-зона с buoyancy (Архимед + сопротивление).

### 5.7. Враги

- Пехота — **KinematicCharacterController** (autostep, snap-to-ground).
- Смерть — **ragdoll** из 5–7 тел с spherical joints, TTL 15 с.

### 5.8. Оптимизация физики

1. **Fixed timestep 60 Гц** + интерполяция.
2. **Sleeping bodies** — не отключать.
3. **Collision groups:** TERRAIN / HUEY / ENEMY / BULLET / DEBRIS.
4. **LOD физики:** близко — полная, средне — без CCD, далеко — выключено.
5. **Пул rigid bodies** для пуль и обломков.
6. **Web Worker** — опционально для сложных сцен.

**Целевые:** <500 активных тел, <2000 collision checks/кадр, <4 мс CPU на физику.

### 5.9. Отладка

`DebugRenderer` — визуализация коллайдеров через `world.debugRender()`, включается по **F3**.

## 6. Вертолёт Bell UH-1 и управление

### 6.1. Модель

- Составные части: фюзеляж, хвост, лопасти, шасси, двери, приборная панель, M60.

## 7. Система вооружения M60

- Скорострельность 600 в/мин, боезапас 500 патронов.
- **Режимы:** hip-fire (spread 0.05) / ADS (spread 0.01).
- Отдача → сдвиг камеры, анимация ствола.
- Перегрев, заклинивание, замена ствола — реалистично.
- **Трассеры:** две линии (белая + чёрная) для видимости.
- **Вспышка:** спрайт 1–2 кадра.
- **Попадания:** raycast → `entity.takeDamage()` → impact FX.

## 8. Система повреждений и разрушения

### 8.1. Зоны

| Зона | HP | Эффект |
|------|-----|--------|
| Двигатель | 100 | Потеря мощности, дым |
| Трансмиссия | 80 | Вибрация, скрежет |
| Хвостовая балка | 120 | Потеря рыскания |
| Лопасти | 150 | Вибрация, потеря lift |
| Кабина | 60 | Трещины, пробоины |
| Топливные баки | 50 | Утечка, пожар |
| Фюзеляж | 200 | Отлёт обшивки |
| Авионика | 40 | Отказ приборов |

### 8.2. Отрыв деталей

`three-pinata` (Voronoi-фрагментация) или простое отсоединение меша → dynamic rigid body с импульсом (см. §5.5). Таблица отрыва: дверь (кабина <40%), панели (фюзеляж <50%), хвостовой винт (хвост <30%), лопасть (лопасти <20%), шасси (фюзеляж <30%), бак (бак <10% → пожар).

### 8.3. Эффекты

Дым, искры, огонь, трещины на стекле (спрайт). При HP критических зон <10% — потеря управления, падение, взрыв, миссия провалена.

## 14. Этапы разработки для LLM

> **Принципы для LLM-разработчика:**
> - Каждый этап завершается **работающим билдом** (`npm run dev` без ошибок).
> - Каждый этап имеет **чёткий критерий приёмки** (что должно работать визуально/функционально).
> - Не переходить на следующий этап, пока текущий не проходит приёмку.
> - На каждом этапе писать **минимум тестов** (Vitest) для критической логики (генерация высот, силы, raycast).
> - Использовать **feature-флаги** в `config.js` для включения/отключения подсистем на время разработки.
> - Физика интегрируется **с этапа 1**, а не «когда-нибудь потом» — это исключает переписывание.

**Задачи:**
1. `npm create vite@latest vietnam-huey -- --template vanilla`

**Критерий приёмки:** `npm run dev` открывает страницу с пустой сценой, FPS-счётчик работает.

### 🔹 Этап 1. Физическое ядро + игровой цикл (1–2 дня)

> **Ключевой этап:** физика закладывается сразу.

**Задачи:**
1. `PhysicsWorld.js` — обёртка Rapier с `Map<body, mesh>`, метод `step()`, `interpolate(alpha)`.
2. `Time.js` — accumulator + fixed timestep 1/60 + интерполяция.
3. `main.js` — игровой цикл: input → forces → physics.step() → interpolate → render.
4. `DebugRenderer.js` — рендер коллайдеров (F3).

### 🧪 Правила для LLM на каждом этапе

1. **Перед началом** — прочитать разделы промпта, относящиеся к этапу.
2. **Не переходить дальше** без прохождения критерия приёмки.
3. **Каждый новый модуль** — с JSDoc-комментариями и тестом (Vitest).
4. **При ошибке** — сначала диагностика (лог в консоль, DebugRenderer), потом фикс.
5. **Рефакторинг** — только если код дублируется 3+ раз или мешает следующему этапу.
6. **Feature-флаги** в `config.js` — чтобы отключать неготовые подсистемы.
7. **Сохранять рабочее состояние** — коммит после каждого этапа.
8. **Документировать** в `CHANGELOG.md` — что добавлено, что изменено.
